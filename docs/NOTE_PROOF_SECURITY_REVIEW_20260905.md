# 保有記録の支出証明：2026年9月5日の再現結果と修正対象

対象は DeFMI `1cf7eef6346f0cf31c933b1449c5e75ec567d4ac`。
正常系の決済・再送試験が通ることは、以下の攻撃に耐える証拠ではありません。
**この版に実資産を入れてはいけません。**

## 再現した不具合

| 番号 | 重要度 | 問題 | 実行した確認 |
|---|---|---|---|
| N1 | 最優先 | 保有記録の所有権と金額を一つの群要素へ足し合わせて証明している。資産の基点が所有権の基点と同じ経路では、金額と使用済み判定値を逆向きに変えても検証を通る。 | 実額1,000に対する2,000の支出を、実際の証明検証器が受け入れた。 |
| N2 | 高 | 公開する使用済み判定値が、台帳の保有記録の公開鍵そのものと一致する。 | 正常な支出について両者の一致を確認した。誰の実名かは別問題だが、使用した保有記録は特定できる。 |
| N3 | 最優先 | 線形関係の検証で「ある値への開示情報を知る」ことしか確認せず、指定した定数との一致を強制していない。支出残差の検証も同型。 | 1への正当な開示証明を、0であるべき残差の検証器が受け入れた。 |
| N4 | 高 | 支出の所属証明が出力先の保有記録全体を拘束していない。発行承認も二つの値を足したものだけに署名する補助経路がある。 | コード上の欠落。修正では出力鍵・暗号化開示情報まで拘束し、出力先差替え・発行承認使い回しの拒否試験を追加する。 |

再現は Softbank の Docker 内で実行した。`defmi/tests/note_security.rs`
の3件すべてが、期待する拒否・非一致にならず失敗した。
記録は `/tmp/defmi-note-security-baseline-20260905.log`。
これは意図的に拒否を要求した回帰試験であり、「無視してよい既存テスト失敗」ではない。

## 修正方針

1. 所有権、同じ保有記録の金額、再使用を検出する値を一緒に検証する既存方式へ移す。
2. 本人を示す公開鍵そのものを使用済み判定値にしない。
3. 金額の残差は、値が0であることを専用に検証する。一般の開示証明と区別する。
4. 古い証明・保存状態を、新形式として黙って受け入れない。移行は明示する。
5. 拒否試験、通常の回帰試験、実際の7計算ノード・5検証ノードの全経路を再実行する。

参照実装は Tari の [Triptych の RingCT 例](https://github.com/tari-project/triptych/blob/bf0cb42fff55636a8bb037020411fb3a050af23f/examples/ringct.rs)。
固定版 `bf0cb42fff55636a8bb037020411fb3a050af23f`、BSD-3-Clause。
そのまま取得した例を Softbank で実行し、1件成功した。
既存の Ristretto、Merlin、curve25519-dalek 4.1.3 と接続でき、基点を指定する正式なAPIがある。
証明アルゴリズム自体はコピーして独自改造せず、固定依存として使用する。

**参照実装自身が実験用・本番不適と明記している。** これを使うだけで本番の暗号監査に
合格したとは扱わない。ここでの目的は再現した欠陥の修正であり、独立した暗号監査と
移行審査は別途必要である。

## 修正と確認結果

- N1/N2：所有権と金額を別の列に保ち、同じ秘密の位置に対するTriptychの共同関係で検証する。使用済み判定値は公開鍵ではなく、ライブラリのリンク値を使う。
- N3：値を0に固定した開示証明を別の用途識別子で生成・検証する。一般の二変数開示証明は残差0の証拠として認めない。
- N4：出力の公開鍵・金額の拘束値・一時鍵・暗号化開示情報を所属証明へ結び付ける。実際に届ける出力と異なれば、使用済み集合も出力も更新しない。補助発行経路の署名も、保有記録全体に結び付ける。
- 使用不可の入力候補は、攻撃者が秘密鍵へ足せる既知の数ではなく、離散対数の未知な点へ置き換える。

Softbank上で607件のテスト、全対象の警告を許さないClippy、整形、
`defmi --no-default-features` 検査が成功した。対象は `defmi`、
`zkfmi-zk`、`qomm-proofs`、`qomm-avalanche-vm`、`zkpi-defmi-sdk`、`qomm-transport`。
新しい7件の支出拒否試験と、旧保存状態の読込み拒否試験を含む。
記録は `/tmp/defmi-note-security-full-gate-retry-20260905.log`、SHA-256
`d1b81d9551494e4b0064fd3e7078febf823d8d74ea490cffa09be905ff69490b`。

旧版で3件の失敗を再現した記録のSHA-256は
`211d15b6cb739daba97dd6b695510c48df1b90abdbcdcb5fc4d4ba6ec95398c8`。
拒否が必要な場所で成功していたことを示す証拠として保持する。

## 保存状態と接続先の移行

新しい支出形式は `QOMMNSP2`、保存状態の方式は `noteProofVersion: triptych_v2`。
`QOMMNSP1` と方式指定のない旧保存状態は読み込まない。新しい使用済み判定値を
旧使用済み集合にそのまま混ぜると、旧版で使った資金を再使用できるおそれがあるためである。

新しい試験ネットワークは初期設定から作る。既存の運用データを削除、初期化、
書換えする自動移行は提供しない。実運用への移行には、旧版での発行・支出・残高を
照合し、不正な状態を引き継がないための別の手順と審査が必要。

この依存単体の検査は成功したが、修正済み版を使うOCLOB全経路の再実行と、
独立した暗号監査・移行審査は別の受入条件である。
